# BT BB30 弹药现状：只读源码核查

核查日期：2026-11-06。对象为 `work/bt_bb30/src/main/` 当前源码与资源；未修改代码、伤害或配方，未启动软件。以下是实现现状，不代表整合包已安装版本的运行验收，也未据此选定后续配方。

## 结论

目前 BT 有“30 发当前弹匣”和换弹动作，但没有真实储备弹药经济。普通机炮换弹会直接填满 30 发，不检查或消耗玩家背包物品；自动战斗同样免费换弹。锁定导弹仅受锁定和 20 秒冷却约束，没有库存。核心消耗战斗充能，使用独立临时射击预算，不扣普通弹匣或弹药物品。

模组只注册召唤信标、电池两个物品，没有机炮弹、弹匣、导弹或核心燃料物品。电池目前是维修、护盾及冲刺能量补给，不是弹药补给。

## 背包、库存与存档

- 玩家背包：未发现弹药读写、`ItemHandler`、弹药槽、弹药类别匹配或弹药扣除逻辑。BT 物品交互中明确扣物品的路径是电池 `shrink(1)`；创造模式不扣电池。`TitanEntity.java:353-357`。
- BT 自身：当前弹匣是同步整数 `MAGAZINE`，没有后备弹箱或容器。不能把 HUD 的 `XO-16 n / 30` 理解成拥有 30 发备弹；`30` 只是弹匣容量。`TitanClient.java:116`。
- 实体存档：保存 `Magazine`、`ReloadRemaining`、`RocketCooldown`、`Core`、`CoreChargeRemaining`、`CoreActiveRemaining`、`CoreShots` 等状态。读档的弹匣被限制在 0—30；旧档无 `Magazine` 时默认 30。没有保存任何真实物品弹药或备弹数量。`TitanEntity.java:701-711, 719-730`。
- 导弹锁定与尚未完成的发射串不保存恢复；读档清空 `rocketTargets`、锁定数和 `rocketBurst`，但保留导弹冷却。`TitanEntity.java:734-735`。
- 世界级 `TitanRegistry` 只存主人、活动机甲 UUID、召唤冷却和撤销记录，不存弹药。`TitanRegistry.java`。

## 对后续弹药成本设计的约束（建议，尚未实施）

1. 先以实际整合包的工业链、TaCZ 弹药/大口径弹现有材料与产出核对成本。此次只读审计未核实其他模组当前配方，不应先编造合成材料 ID，也不能直接用少量铁和红石定稿机炮弹。
2. XO-16、追踪导弹应有可持久化的独立储备，明确一次物品代表一发还是一整箱；玩家驾驶和自动战斗必须共用扣弹入口，不能 AI 免费射击。
3. 扣弹应与换弹提交点匹配，处理取消、卸载、读档、重召、换驾驶员及半匣换弹，不允许免费复制，也不应一次失败换弹重复扣物品。
4. 核心当前是战斗充能大招；是否再消耗实体弹药应作为明确设计决定，不能因复用 `mainFire()` 意外扣普通弹匣，也不能使资源约束被核心或新召唤绕过。
5. 当前电池只补生存与冲刺资源。若新增供弹交互，提示与物品语义应与电池分开；便宜维修电池不能无意成为廉价无限导弹来源。
